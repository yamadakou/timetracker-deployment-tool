# 詳細設計: デプロイのグループ（用途・利用者ごとの管理）

- 対象ブランチ: `feature/desktop-app`
- 関連: [共通部分の構造](README.md)の 4（Azure に作るものと管理タグ）・[`desktop-jobs.md`](../desktop/desktop-jobs.md)の 6.1〜6.4（利用可能期限のタグ・デプロイの一覧）・[`desktop-wizard.md`](../desktop/desktop-wizard.md)の 7（表）
- 状況: 案（REVIEW_ISSUES No.77）。論点（9）はオーナーの回答待ち
- 一次情報の確認日: 2026-10-28（出典は 10）

## 1. 目的
実際の運用でデプロイした Timetracker を、用途（評価・研修・本番の部署向けなど）や利用者（チーム・顧客）ごとに分けて管理できるようにする。

- デプロイした Azure のリソースに、グループ名を Azure のタグで付ける（PC ではなく Azure に置くため、別の PC・CLI・MCP サーバーでデプロイしたものも同じように分けられる）
- デプロイの一覧に「グループ」の列を足し、グループで絞り込み・並べ替えできるようにする
- 新しいデプロイで、グループ名を任意の項目として入れられるようにする
- デプロイの一覧で選んだ行のグループ名を、まとめて変えられるようにする

## 2. スコープ
| 項目 | 扱い |
|---|---|
| グループのタグの書き込み（デプロイのとき・一覧でまとめて変えるとき） | ✔ |
| デプロイの一覧の「グループ」の列・絞り込み・並べ替え | ✔ |
| デスクトップアプリの設定（④ 相当の入力）・テンプレート・設定の Markdown のコピー | ✔ |
| CLI の `--group`・MCP の `group` | Q4 で決める |
| グループの一覧を別に管理する（グループの作成・名前の変更の画面） | ✘（グループは、タグの値があるかどうかだけで決まる。名前を変えるには、まとめての変更を使う） |
| グループごとの権限・料金の集計 | ✘（Azure のロールとコスト管理の範囲。タグはコスト管理でも使える） |

## 3. タグ
| 項目 | 決めたこと（案） | 一次情報 |
|---|---|---|
| キー | `tt-group`（Q1。ほかの管理タグ `tt-app-name`・`tt-expires-at` と同じ接頭辞） | タグの名前は大文字と小文字を区別しない（出典 1） |
| 値 | 利用者が入れたグループ名（前後の空白を除く）。空なら付けない（タグを消す） | 値は大文字と小文字を区別する（出典 1） |
| 付けるもの | 利用可能期限のタグ（`tt-expires-at`）と同じ: 3 つの Container App・ストレージアカウント（永続化するとき）。Container Apps Environment には作るときだけ付ける（タグを変えるだけでも数分「更新中」になるため。`desktop-jobs.md` の 6.1） | — |
| 読み方 | Resource Graph で読む今のデプロイの一覧（`DeploymentCatalog`）で、Container App とストレージアカウントの値をまとめる。どちらも無ければ Environment の値。値が食い違えば（一部だけ変えられた・ポータルで変えたなど）、Timetracker の Container App の値を出し、食い違いを示す（期限の食い違いの表示と同じ） | 出典 3 |
| 守り | タグは平文で、コストの報告・デプロイの履歴などから見える（出典 1）。グループ名に秘密の情報を入れないよう、入力欄に注意を書く | 出典 1 |

### 3.1 値の決まり（案。Q3）
- 長さは 1〜64 文字（Azure の上限は 256 文字。出典 1。表の列で読める長さにする）
- 制御文字（改行・タブなど）は使えない。日本語は使える（Azure の注意は、仮想マシンのメタデータの読み込みについてで、Container Apps には当たらない。出典 1）
- 大文字と小文字は区別して保存するが、一覧の絞り込み・並べ替えと、入力の候補では区別しない（「Sales」と「sales」を同じグループとして束ね、表には最初に見つかった書き方を出す）。入力では、既にあるグループ名を候補に出して、書き方の揺れを防ぐ

## 4. デプロイのとき
| 項目 | 決めたこと（案） |
|---|---|
| 入力 | デスクトップアプリ: 「新しくデプロイ」の設定（④ の利用可能期限の近く）に「グループ（任意）」の入力欄。デプロイの一覧にあるグループ名を候補に出す（自由にも入れられる）。テンプレートに保存し、設定の Markdown のコピーにも出す |
| 計画 | 計画の表示に「グループ: …」を出す。既にあるデプロイで、入れたグループが今と違えば「グループを … から … に変えます」と出す |
| 既にあるデプロイへの再デプロイ（Q2） | 入力が空なら、今のグループを引き継ぐ（タグを書き換えない）。外したいときは、デプロイの一覧で「グループを外す」 |
| 書き込み | `DeploymentRunner` が利用可能期限と同じ「ライフサイクルのタグ」として書く（`DeployOptions.LifecycleTags`）。利用者が付けたほかのタグは残す（`ManagedTags.WithManagedTags` と同じ扱い） |

## 5. デプロイの一覧
| 項目 | 決めたこと（案） |
|---|---|
| 列 | 「グループ」（アプリ名の右）。グループの無い行は空。食い違いがあれば「（食い違い）」を添え、マウスを置くとリソースごとの値を出す |
| 並べ替え | 見出しで、グループ名の順（大文字と小文字を区別しない。グループの無い行は最後） |
| 絞り込み（Q5） | 見出しの「▽」で、「すべて」「グループなし」と、今の一覧にあるグループ名の一覧から 1 つを選ぶ（状態の絞り込みと同じ形） |
| まとめての変更（Q6） | 行を選び、表の上の操作に「グループ名」の入力欄（候補つき）と「グループを変える」「グループを外す」。選んだ行のうち、同じ対象の終わっていないジョブがある行は外し、その数を伝える（期限の変更と同じ）。変えた行は、一覧を読み直さずに表示を変える |
| 書き込み | `DeploymentMaintenance.ChangeGroupAsync`（期限の変更 `ChangeExpiryAsync` と同じく、本ツールで作った Container App とストレージアカウントのうち、管理タグが一致するものだけのタグを書き換える） |
| 確認 | まとめての変更は、件数と新しいグループ名を示して確かめてから行う（Q6） |

## 6. CLI・MCP サーバー（Q4）
- CLI: `deploy --group <名前>`（任意）。一覧が無いため、まとめての変更は無い
- MCP: `plan_deployment` の引数 `group`（任意）。`get_deployment_info` と Resource の `deployment` で今のグループを返す
- 名前の決まりと再デプロイの扱いは 3.1・4 と同じ（Domain に置く）

## 7. 部品
- Domain: `DeploymentGroup`（キー `tt-group`、値の決まりの検証・正規化、読み取りでのまとめ方）。`DeployInput.Group`・`DeployOptions.Group`
- Application: `DeploymentRunner` のライフサイクルのタグに足す。`DeploymentPlanner` の計画に、今のグループと変えるかを足す。`DeploymentCatalog`（`DeploymentEntry.Group`・`GroupDiffers`）。`DeploymentMaintenance.ChangeGroupAsync`
- Desktop.Core: `SettingsViewModel.Group`（テンプレート・初期値・Markdown）、`DeploymentListViewModel`（列・並べ替え・絞り込み・まとめての変更）、`DeploymentRowViewModel.GroupText`
- 権限: タグの書き換えは、期限の変更と同じ権限（Container App・ストレージアカウントへの書き込み。Contributor）で足りる。新しい権限の確認は要らない

## 8. テスト
- Domain・Application: 値の検証（長さ・制御文字・前後の空白）、ライフサイクルのタグへの追加、空なら引き継ぐこと、まとめ方（食い違い・Environment だけ）、`ChangeGroupAsync` の対象（管理タグの一致するものだけ）
- Desktop.Core: 入力と候補、テンプレートの保存と読み込み、計画の表示、列・並べ替え・絞り込み（大文字と小文字を区別しない）、まとめての変更（ジョブのある行を外す・確認・表示の更新）。分岐網羅率 100%
- UI テスト（CI）: 列の見出しと絞り込みの AutomationId（`XamlContractTests`）
- Desktop System Test: グループを付けてデプロイし、一覧で変えて、絞り込めること

## 10. 出典（2026-10-28 に確認）
1. [Use tags to organize your Azure resources and management hierarchy](https://learn.microsoft.com/azure/azure-resource-manager/management/tag-resources)（2025-09-15 更新）: 1 つのリソースに 50 個まで。名前は 512 文字（ストレージアカウントは 128 文字）、値は 256 文字まで。名前に `< > % & \ ? /` は使えない。名前は大文字と小文字を区別せず、値は区別する。タグは平文で、コストの報告・デプロイの履歴などから見えるため、秘密の値を入れない。英語以外の文字は、仮想マシンの IMDS でのメタデータの読み込みで失敗することがある。リソースは、リソースグループのタグを引き継がない
2. 同上: タグを付けるには、リソースへの書き込み（Contributor など）か、`Microsoft.Resources/tags` への書き込み（Tag Contributor）が要る
3. 本ツールの今の実装: Resource Graph での一覧（`ResourceGraphDeploymentDirectory`・`DeploymentCatalog`）と、期限のタグの書き換え（`DeploymentMaintenance.ChangeExpiryAsync`）。`desktop-jobs.md` の 6.1・6.4
