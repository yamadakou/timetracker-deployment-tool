# デスクトップアプリの Windows での確認手順

デスクトップアプリ（詳細設計 [`desktop-app.md`](desktop-app.md)、REVIEW_ISSUES No.49）を Windows の PC で動かし、自動のテストでは確かめられないこと（WAM でのサインイン、Windows の通知・通知領域・サインイン時の起動、見た目）を確かめる手順です。自動のテストで確かめていることは 3 章にまとめ、実機では確かめません。

1. 準備（パッケージの取得と導入）……2 章
2. 自動のテストで確かめていること……3 章
3. 実機で確かめること……4 章（4.3 の本物の Azure は任意）
4. 後片付けと記録……6 章

- **所要時間**: 30 分ほど（4.3 も行うと 1 時間ほど。Environment の作成に 5〜15 分、削除に 10〜15 分かかります）
- **料金**: Container Apps（と、永続化を確かめる場合はストレージアカウント）の料金が少しかかります。最後に削除します
- **結果の記録先**: `docs/REVIEW_ISSUES.md` の No.49 と、詳細設計の「12. 実装フェーズ」の実施結果

## 1. この手順で使う言葉
| 言葉 | 意味 |
|---|---|
| [MSIX](https://learn.microsoft.com/ja-jp/windows/msix/overview) | Windows のアプリのパッケージの形式。Store からも、ファイルからも導入できる |
| [サイドロード](https://learn.microsoft.com/ja-jp/windows/application-management/sideload-apps-in-windows) | Store を通さずに、パッケージのファイルからアプリを導入すること。署名されたパッケージが必要 |
| [WAM](https://learn.microsoft.com/ja-jp/entra/msal/dotnet/acquiring-tokens/desktop-mobile/wam) | Windows の Web アカウント マネージャー。Windows にサインインしているアカウントで、Azure にサインインできる |
| 計画 | アプリは、Azure を変更する前に、読み取りだけで計画を作り、利用者が確かめてから実行する（CLI の `--dry-run`、MCP の `plan_*` と同じ） |
| アプリのデータのフォルダー | アプリが設定・予定・終わったジョブの記録・診断用のログ・サインインの情報を置くフォルダー（2.4） |

## 2. 準備
### 2.1 使うもの
- [ ] Windows 10（1809 以降）または Windows 11 の PC（x64 または arm64）
- [ ] 確認に使う Azure のサブスクリプションと、そこで Contributor 以上のロールを持つアカウント（[README の必要な RBAC ロールと権限](../../../README.md)）。MFA を登録してあること（Azure の作成・削除には MFA が必須）
- [ ] リソースプロバイダー `Microsoft.App`（と、永続化を確かめる場合は `Microsoft.Storage`）が登録されている
- [ ] （Dry-run の起動の確認をする場合）Docker Desktop

### 2.2 パッケージを取得する
CI（`ci.yml` の `desktop` ジョブ）の成果物 `ttdeploytool-desktop-msixupload`、またはリリースの `ttdeploytool-desktop-vX.Y.Z.msixupload` を取得します。

`.msixupload` と中の `.msixbundle` は zip の形式です。拡張子を `.zip` に変えて展開すると、`.msixbundle` が、さらに展開すると x64 と arm64 の `.msix` が出てきます。

### 2.3 導入する
Store の限定公開で導入できる場合は、Store から導入します（この場合 2.2 は不要）。Store を使わない場合は、次のどちらかでサイドロードします。CI とリリースのパッケージは署名されていないため、署名か開発者モードが必要です。

- **開発者モード + Visual Studio**: リポジトリを取得し、`TTDeployTool.Desktop.slnx` を Visual Studio で開き、`TTDeployTool.Controller.Desktop` をスタートアップ プロジェクトにして、プラットフォーム `x64`（Arm の PC は `ARM64`）・起動プロファイル「TTDeployTool.Controller.Desktop (Package)」で実行する（[WinUI 3 の開発環境](https://learn.microsoft.com/ja-jp/windows/apps/get-started/start-here)。Windows の「設定」→「システム」→「開発者向け」で開発者モードを有効にする）
- **自己署名の証明書で署名して導入**: [自己署名の証明書を作り](https://learn.microsoft.com/ja-jp/windows/msix/package/create-certificate-package-signing)、`.msix`（x64 または arm64）に [SignTool で署名](https://learn.microsoft.com/ja-jp/windows/msix/package/sign-app-package-using-signtool)し、証明書を「信頼されたユーザー」に入れてから、`.msix` を開いて導入する。証明書の発行者（`CN=...`）は、マニフェストの `Publisher`（CI のパッケージは `CN=TTDeployTool`）と同じにする

### 2.4 アプリのデータのフォルダー
アプリは、設定・予定・終わったジョブの記録・診断用のログを、Windows のユーザーごと・アプリごとのフォルダーに置きます（コードは `src/TTDeployTool.Controller.Desktop/Services/DesktopSettings.cs` の `DataDirectory`）。確認の中で中身を見るとき（5.3 の 9・11 など）と、うまくいかないとき（7 章）に使います。

| 導入の方法 | フォルダー |
|---|---|
| パッケージ版（Store・評価版・Visual Studio の「(Package)」の起動プロファイル） | `%LOCALAPPDATA%\Packages\TTDeployTool_<発行元のハッシュ>\LocalState`（[ApplicationData.LocalFolder](https://learn.microsoft.com/ja-jp/uwp/api/windows.storage.applicationdata.localfolder)） |
| パッケージにしないで起動した場合 | `%LOCALAPPDATA%\TTDeployTool` |

`<発行元のハッシュ>` は署名した発行元から決まる文字列です。PowerShell で次を実行すると、パッケージ版のフォルダーを開けます（アプリの「設定」の画面の「ログのフォルダーを開く」で開く `logs` の、1 つ上のフォルダーでもあります）。

```powershell
explorer "$env:LOCALAPPDATA\Packages\$((Get-AppxPackage -Name TTDeployTool).PackageFamilyName)\LocalState"
```

| ファイル | 中身 | 消えるとき |
|---|---|---|
| `preferences.json` | 同時に実行する数・テンプレート（パスワードなし）・出した期限の通知・まだ始めていない予定（「予定を残す」を選んだデプロイは、パスワードを DPAPI で暗号化して含む）・前回のサインイン時の起動 | 予定は、始めたとき・取り消したとき |
| `job-history.json` | 終わったジョブの記録（結果・ログ・日時。パスワードなし） | 180 日・500 件を超えたとき、「記録から削除」 |
| `authentication-record.json` | 前回サインインしたアカウントとテナントの識別子（秘密の情報なし） | サインアウト |
| `logs\ttdeploytool-desktop-yyyyMMdd.log` | 診断用のログ（パスワード・トークン・アカウント名なし） | 7 日 |

- ファイルを見たり消したりするときは、先に通知領域のメニューの「終了」でアプリを終えます（ウィンドウを閉じても、ジョブや期限があると通知領域に残って動いているため）。動いている間に消しても、アプリが次に保存するときに書き戻します
- 設定・予定・記録を最初の状態に戻したいときは、アプリを終えてから `preferences.json`・`job-history.json` を消します（サインインもやり直すときは `authentication-record.json` も）
- アプリをアンインストールすると、`LocalState` のフォルダーは中身ごと消えます。評価版と、Visual Studio で配置した開発用のアプリは、同じ名前と発行元のため同じフォルダーを使います
- Azure へのサインインのトークンのキャッシュ（Azure.Identity の `TokenCachePersistenceOptions`、名前は `ttdeploytool-desktop`、DPAPI で保護）は、このフォルダーには置きません。Azure.Identity の既定では `%LOCALAPPDATA%\.IdentityService` の下で、パッケージ版では Windows がパッケージの `LocalCache\Local` の下に振り替える見込みです（[パッケージ化したデスクトップアプリの AppData の扱い](https://learn.microsoft.com/ja-jp/windows/msix/desktop/desktop-to-uwp-behind-the-scenes)）。実際の場所とアンインストールで消えるかは、詳細設計の 11 の 2 として、6 章で記録します（`Get-ChildItem -Recurse -Force "$env:LOCALAPPDATA\Packages\<パッケージ ファミリ名>\LocalCache", "$env:LOCALAPPDATA\.IdentityService" -Filter "ttdeploytool-desktop*"` で探せます）

## 4. 実機で確かめること
自動にできない（Windows とアプリの外の画面に頼る）ものと、見た目だけを確かめます。

### 4.1 サインイン（WAM）
| # | 操作 | 確かめること |
|---|---|---|
| 1 | 「サインイン」を押す | WAM のアカウントの選択（または Windows のアカウントでのサインイン）が表示される。サインインすると、アカウント名が表示され、「サインイン」が押せなくなり、「サインアウト」が押せるようになる |
| 2 | サインインの後 | サブスクリプションの一覧に、入れるテナントのサブスクリプションが「名前（ID、テナント名）」で並ぶ。読めないテナントがあれば、その旨が一覧の下に出る（ほかのテナントの一覧は出る）。サブスクリプションが 1 つなら選ばれている |
| 3 | アプリを閉じて、もう一度起動する | 対話なしでサインインした状態に戻り、サブスクリプションが読まれる |
| 4 | 「サインアウト」を押し、アプリを再起動する | サインインしていない状態で始まる。もう一度「サインイン」する |
| 5 | サインインの画面を閉じる（キャンセル） | エラーは表示されない |

### 4.2 Windows の通知・通知領域・サインイン時の起動
| # | 操作 | 確かめること |
|---|---|---|
| 1 | 「新しくデプロイ」で数分後の予定を入れ、ウィンドウを閉じる | ウィンドウが隠れ、通知領域にアイコンが出る。通知が Windows の通知として出る。アイコンにマウスを置くと「TTDeployTool（予定 1）」 |
| 2 | もう一度閉じ、予定の時刻を待つ | ジョブが終わると通知が出る。通知を押すと、隠したウィンドウが出る |
| 3 | 予定の時刻に、ウィンドウを隠したまま MFA などのサインインが要る状態にする（任意） | WAM のサインインの画面が出るか。出ない・サインインしない場合は、10 分で「サインインの画面で 10 分以内にサインインされなかったため、ジョブを止めました。」で失敗し、通知が出る |
| 4 | 予定のジョブがある状態で、通知領域のアイコンを右クリックし「終了」を選ぶ | ウィンドウが出て、確認が出る。「終了する」でアプリが終わり、アイコンが消える |
| 5 | 期限日のあるデプロイを初めて「今すぐ実行」か「予定に追加」し、「Windows のサインイン時に起動しますか？」で「起動する」を選ぶ | タスク マネージャーの「スタートアップ アプリ」に TTDeployTool が「有効」で出る |
| 6 | Windows からサインアウトし、サインインし直す | ウィンドウは出ず、通知領域にアイコンが出る。前回のサインインが復元できなければ「サインインが必要です」の通知が出て、押すとウィンドウが出る。「設定」の「Windows との連携」に「前回のサインイン時の起動: （日時）」が出る |
| 7 | タスク マネージャーでスタートアップを無効にする・Windows の設定で TTDeployTool の通知をオフにし、「設定」の「状態を読み直す」を押す | 「タスク マネージャーの…で無効にされています」「このアプリの通知が、Windows の設定で止められています」と出る（Windows が状態を正しく返すことの確認。表示はモックの UI テストで確かめている）。元に戻す |

### 4.3 本物の Azure とパスワードの暗号化（任意。Desktop System Test で通しの流れは確かめている）
| # | 操作 | 確かめること |
|---|---|---|
| 1 | 完了したデプロイの「Timetracker を開く」 | ブラウザーが開き、セットアップの画面に転送される |
| 2 | 「予定を残す」をオンにしたデプロイの予定を入れ、通知領域の「終了」でアプリを終え、起動し直してサインインする（フォルダーは 2.4） | 「前回の予定を戻しました」の通知が出て、予定が戻る。`preferences.json` にパスワードが平文で無い（DPAPI で暗号化・復号できることの確認） |
| 3 | DB のデータを「Azure Files に永続化する」にして計画 → 実行 → 「DB のデータを残す」で削除する | 計画にストレージアカウントと料金の案内が出て、削除の後もストレージアカウントが残る（[DB データの永続化の詳細設計](../common/db-persistence.md)） |
| 4 | Azure portal で 3 つの Container App の `tt-expires-at` を過去の時刻にし、起動し直してサインインする | 期限での削除のジョブが登録され、DB のデータも含めて削除される（登録までは、モックの UI テストで確かめている） |

|---|---|---|

### 5.1 UI テストで確かめる（半自動。任意）
Desktop System Test と同じ流れ（サブスクリプションの読み込み → 状態の確認 → 計画 → デプロイ → 状態の確認 → 削除）を、UI テスト（[UI テストの詳細設計](desktop-ui-tests.md)の 6）で自動で操作できます。サインインだけ、WAM の画面で行います。
1. Visual Studio でアプリを配置する（「ビルド」→「ソリューションの配置」）
2. PowerShell 7 でリポジトリのフォルダーに移り、`./scripts/run-desktop-ui-tests.ps1 -SubscriptionId <サブスクリプション ID>` を実行する（リソースグループは既定で `rg-ttui-<日時>`。`-ResourceGroup` で変えられる）
3. 表示された内容（作るもの・料金・所要時間 20〜30 分）を確かめて `yes` と入力する。サインインしていなければ、アプリのサインインの画面でサインインする（最大 5 分待つ）
4. 終わったら、リソースグループを削除するかを聞かれる（`az` がある場合）。結果は `TestResults/desktop-ui`（trx、失敗したときのスクリーンショット、診断用のログの写し）

テストの間は、アプリのウィンドウを操作しないでください（テストが操作する要素を見失います）。

## 7. うまくいかないとき
| 症状 | 考えられる原因 |
|---|---|
| `.msix` を開いても導入できない（署名が無い・信頼されていない） | 2.3 の署名と証明書の信頼が必要。証明書の発行者がマニフェストの `Publisher` と違う |
| サインインでエラーになる（`AADSTS50011` など、リダイレクト URI の不一致） | アプリ登録のリダイレクト URI に `ms-appx-web://Microsoft.AAD.BrokerPlugin/<クライアント ID>` が無い（[提出手順](desktop-app-store.md)の 2 章）。クライアント ID を渡さずにビルドした場合は、Azure.Identity の既定（開発用）を使う |
| 実行で「多要素認証（MFA）が必要です」と表示される | MFA を行わずにサインインした。サインインし直し、MFA を行う（詳細設計 5.3） |
| 計画で権限が不足している | アカウントに Contributor 以上のロールが無い（README の必要な RBAC ロールと権限） |
| サブスクリプションが一覧に出ない | そのテナントで MFA などのため読めない（一覧の下の注意を確かめる）。サインインし直すと読める場合がある |
| 起動し直しても、予定や終わったジョブの記録が戻らない | アプリのデータのフォルダー（2.4）に `preferences.json`・`job-history.json` があるかを確かめる。無ければ保存できていない（ログに理由がある）。予定は、保存したときと同じアカウントでサインインしたときに戻る。暗号化したパスワードは、同じ PC の同じ Windows ユーザーでしか復号できない |
| 設定・予定・記録を初めからやり直したい | アプリを終えてから、アプリのデータのフォルダー（2.4）の `preferences.json`・`job-history.json` を消す |

原因が分からない場合は、「設定」の画面の「ログのフォルダーを開く」（アプリのデータのフォルダーの `logs`。2.4）で診断用のログ（`ttdeploytool-desktop-yyyyMMdd.log`。詳細設計 7.2）を開き、起きた時刻の前後を確かめる（Issue に添付する場合も、パスワード・トークン・アカウント名は含まれない）。
