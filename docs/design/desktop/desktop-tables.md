## 4. 列の操作（論点 Q3）
依頼の 5 つ: 列の幅の変更・列の順序の変更（チェックの列は左端に固定）・列の表示 / 非表示（チェックの列は必ず表示）・固定の列（チェックの列は左端に固定し、複数の列を固定できる）・はみ出るときは列の幅を縮めず横のスクロール。

### 4.1 共通の決まり（どの案でも）
- 列の設定（幅・順序・表示・固定の数）は、表ごとに、アプリのデータの `preferences.json` に保存し、次の起動でも同じにする。表の上に「列の設定を初期値に戻す」を置く
- チェックの列（行の選択）は、いつも左端で、隠せない・動かせない・幅を変えられない
- 並べ替え（見出しを押す）と絞り込み（▽）は、今の決まり（Core の `DeploymentListViewModel`・`JobListViewModel`）のまま使う

- ジョブの一覧にも、デプロイの一覧と同じページ（20・50・100 件ずつ。既定 20）と「前のページ」「次のページ」、件数の表示（「1〜20 件目を表示（絞り込んだ N 件 / 全 M 件）・1 / 3 ページ」）を付ける。前回までのアプリの記録（最大 500 件）が増えても、表が長くなりすぎない

### 9.1 分かったことの意味
- 画面の読み上げは、セルごとに列の見出しを読むので、表の中身は分かる。見出しは Invoke に対応するので、UI Automation の道具からは見出しで並べ替えができる
- ただし、見出しは木に出ず、キーボードのフォーカスも当たらないため、**キーボードだけの利用者や、木をたどる読み上げの操作からは、見出しでの並べ替え・絞り込み（▽）・幅と順序の変更に届かない**
- UI テストは、今の「AutomationId で見出しのボタンを押す」形から、「セルからたどった見出しを Invoke する」形と、表の上の操作で確かめる形に変える。行の無い表では見出しに届かないので、空の表の確かめ方は表の上の操作にする

### 9.2 Microsoft の TableView（実験版）との違い
Microsoft Learn の「TableView control」（出典 9）は、Windows App SDK 2.5.4-experimental の `Microsoft.UI.Xaml.Controls.Tabular.TableView` で、WinUI.TableView（別物・API も違う）ではない。実験版で、文書には「Don't use them in production apps.」とある。2.5.4-experimental では、選べるのは 1 行だけ・列の順序は変えられない・見出しからキーボードで並べ替えられない。複数選択・列の順序の変更が要る今回の用途と、ストアで配る製品には使えない。安定版が出たら、乗り換えを改めて検討する

### 9.3 論点 Q5: 置き換えるか
| 案 | 内容 | メリット | デメリット |
|---|---|---|---|
| **A（推奨）** | WinUI.TableView に置き換える。見出しでの操作は、マウス・UI Automation の道具ではそのまま使い、キーボードだけの利用者のために、表の上に「並べ替え」（列と向き）・「絞り込み」と、「列の設定」の画面（表示 / 非表示・順序（上へ・下へ）・幅・固定する列の数・初期値に戻す）も置く。見出しは文字だけにする | マウスでは表計算に近いドラッグの操作ができ、キーボードだけの利用者も同じことが別の入口からできる。表の中身の読み上げは今より良くなる（セルごとに列の名前を読む） | 同じ操作の入口が 2 つになり、画面の部品が増える |
| B | WinUI.TableView に置き換え、見出しの操作だけにする（表の上の操作・列の設定の画面は作らない） | 画面が簡単で、作る量が少ない | キーボードだけの利用者は、並べ替え・絞り込み・列の操作ができない |
| C | 置き換えず、4.2 の C（今の表のまま、幅のつまみ・列の設定の画面・横のスクロールを自作。固定の列は見送る）にする | 新しい依存が無い。見出しも木に出る今の作りを保てる | 見出しのドラッグでの順序の変更と固定の列ができない。作る量は A と同じくらい |

あわせて、見出しが木に出ないことと `GetColumnHeaders` が空を返すことを、WinUI.TableView に報告するか（外部への投稿）もオーナーに確かめる。

### 10.2 論点 Q6: 見出しでの絞り込み（▽）の作り
今の絞り込みは、列ごとに形が違う（サブスクリプション・グループ・状態・期限: 1 つを選ぶ、リソースグループ・アプリ名・対象: 文字の一部、日付の列: 範囲）。

| 案 | 内容 | メリット | デメリット |
|---|---|---|---|
| **A（推奨）** | 今の ▽ と、その中身（選ぶ・文字・日付の範囲）を、そのまま見出しの中（見出しの文字の右）に置く。TableView の内蔵の ▽（Excel 風の値の一覧）は使わない（`CanFilterColumns="False"`）。絞り込みの決まり（Core）は変えない | 今と同じ操作で、使い方が変わらない。日付の範囲・文字の一部での絞り込みが残る。▽ はボタンなので、Tab キーで届く見込み（実装の後に確かめる） | 見出しの中に自分のボタンを置くため、見出しの見た目の作り（テンプレート）を列ごとに用意する |

### 10.3 論点 Q7: 列の表示 / 非表示と、固定する列の操作
TableView には、列を隠す・固定する列を変える操作の画面が無い（プロパティだけ）。

| 案 | 内容 | メリット | デメリット |
|---|---|---|---|
| **A（推奨）** | 見出しを右クリックしたときのメニューにまとめる: 「この列を隠す」「表示する列」（すべての列のチェックの一覧。最後の 1 列は隠せない）「この列まで固定する」「固定をやめる」「列の設定を初期値に戻す」 | 見出しでの操作だけ（Q5）にそろう。表の上に部品が増えない。表計算と同じく、見出しの右クリックで探せる | 右クリックを知らないと見つけにくい（表の下に「見出しの右クリックで、列を隠す・固定する」と 1 行添える）。見出しにキーボードのフォーカスが当たらないため、キーボードだけでは開けない（Q5 の B で受け入れた範囲） |

### 10.3.1 WinUI.TableView の中の例外（Desktop System Test、2026-10-29）
TableView 1.5.1 は、行を 1 つだけ選ぶと、その行の番号で `ScrollRowIntoView` を後から（`DispatcherQueue.TryEnqueue`）実行する。それまでに表の行が減ると、番号が範囲の外になり `ArgumentOutOfRangeException` になる（行を選んだデプロイの削除が終わり、一覧を続けて作り直したとき。run 40864735420 でアプリが終了した）。部品の中の順番のため、アプリの側では防げない。この例外だけを、処理されなかった例外の扱い（`App.UnhandledException`）で記録して続ける（Core の `KnownUiErrors.IsTableViewScrollRace`。選んだ行を表示させる処理が 1 回行われないだけ）。ほかの例外は今までどおり
- 同じ形の確認（2026-10-29。v1.5.1 のソースで、後から実行する処理〔`DispatcherQueue.TryEnqueue`・`async void`・`Task.Yield`・`Task.Delay`〕約 30 か所を確かめた）:
  - 同じ不具合（覚えた行の番号で、範囲を確かめずに `Items[index]`）: 選択の変更（`TableView_SelectionChanged`）と、読み取り専用の表でセルを押した・キーボードで移ったとき（`SelectRows` の `ScrollRowIntoView(slot.Row)`。この表は `IsReadOnly="True"` のため通る）の 2 か所。どちらも `ScrollRowIntoView` の中で起きるため、上の扱いで続けられる
  - 番号を確かめているもの（問題なし）: `GetCellFromSlot`（`slot.IsValid`）、`ScrollIntoViewAfterDetailsPaneVisibility`（番号と中身が同じかを確かめる）、`ScrollRowIntoView` の後半（`ContainerFromIndex` は無ければ null）、`ApplyPendingCellStates`（今ある行だけ）
  - 番号を使わないもの: 行の色・選択の印・行見出しの幅・列見出しの幅の更新、ドラッグでの選択（この表では使わない）、グループ化（`CanGroupColumns="False"`）、貼り付け・CSV の書き出し（読み取り専用で使わない）
  - アプリの側: 後から実行するのは `TableBinder` の並べ替え（列の向きを読むだけ）だけで、行の番号は使わない
  - 作者の Issue: `ScrollRowIntoView`・`ArgumentOutOfRangeException` で探したが、同じ報告は無い（見出しの幅が負になる例外 #437 は 1.5.1 で直っている）。修正案つきで報告した（[#478](https://github.com/w-ahmad/WinUI.TableView/issues/478)、2026-10-29。本文は [`upstream-tableview-issue.md`](upstream-tableview-issue.md)）
