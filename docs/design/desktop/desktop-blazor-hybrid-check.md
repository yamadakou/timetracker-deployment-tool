# Blazor Hybrid 版の実機での確認

- 目的: WinUI 3 版と同じ機能を実装した Blazor Hybrid 版（[`desktop-blazor-hybrid.md`](desktop-blazor-hybrid.md) の 16 章）を、オーナーの PC（Windows 11）で確かめる。CI では確かめられないもの（WAM のサインインの窓が前に出ること・見た目・本物の Azure での動き・人の操作での時刻の選択と日本語の変換）が中心
- 対象: CI（`ci.yml` の `blazor-prototype-windows` ジョブ）の成果物 `ttdeploytool-blazor-prototype-msix`（7 日で消える）。評価版（Desktop Preview）とは別のアプリ（`TTDeployTool.BlazorPrototype`）で、今の TTDeployTool と並べて入る。アプリのデータ（設定・ジョブの記録）も別
- **本物の Azure を使う**: サインインは WAM、Azure の読み書きは本物（モックではない）。デプロイ・削除をすると Azure が変わり、デプロイしたものには料金がかかる。3 章の必須の項目は Azure を変えない（削除は「予定に追加」だけにして、実行の前に取り消す）。デプロイと削除の実行は任意（3.8）で、テスト用のリソースグループで行う
- サインインのアプリ登録: CI の MSIX は、ビルドでクライアント ID を渡していない（Azure.Identity の既定。開発用）。会社のテナントの設定でサインインを断られたら、出た文字を記録する（評価版と同じクライアント ID で作り直す）
- 記録: `docs/REVIEW_ISSUES.md` の No.79。試作のときの確認（通知など。2026-10-31 にすべて OK）は設計書の 15.2

## 1. 受け取るもの
CI の実行の **Summary** の下の **Artifacts** から `ttdeploytool-blazor-prototype-msix` を取り出し、展開する。

| ファイル | 内容 |
|---|---|
| `TTDeployTool-BlazorPrototype-x64.msix` | Blazor Hybrid 版のアプリ（x64 だけ） |
| `TTDeployTool-BlazorPrototype.cer` | その実行だけで作った署名の証明書（公開鍵だけ） |
| `CHECK.md` | この手順書 |

## 2. 入れる
1. 前に試作（2026-10-31 の確認のもの）を入れたままなら、先に外す（管理者でない PowerShell）。証明書が実行ごとに違うため、上書きでは入らないことがある。

   ```powershell
   Get-AppxPackage -Name TTDeployTool.BlazorPrototype | Remove-AppxPackage
   ```
2. スタート メニューで「PowerShell」を右クリックし、「**管理者として実行**」で開いて、証明書を「ローカル コンピューター」の**信頼されたユーザー**に入れる（パスは置き換える）。

   ```powershell
   Import-Certificate -FilePath "C:\Users\<名前>\Downloads\ttdeploytool-blazor-prototype-msix\TTDeployTool-BlazorPrototype.cer" -CertStoreLocation Cert:\LocalMachine\TrustedPeople
   ```
3. 管理者でない PowerShell で、アプリを入れる。

   ```powershell
   Add-AppxPackage -Path "C:\Users\<名前>\Downloads\ttdeploytool-blazor-prototype-msix\TTDeployTool-BlazorPrototype-x64.msix"
   ```
4. スタート メニューの「**TTDeployTool（Blazor Hybrid の試作）**」で起動する（名前は試作のまま。ウィンドウの題は「TTDeployTool」）。サインインの画面が出る。

## 3. 確かめること
各項目の結果（✔ / ✘ と、気づいたこと）を 5 章の表に記録する。今の WinUI 3 版と並べて動かして、見比べてもよい。

### 3.1 サインイン（WAM。必須）
| # | 操作 | 確かめること |
|---|---|---|
| 1 | 「サインイン」を押す | Windows のアカウントを選ぶ窓（WAM）が、**TTDeployTool のウィンドウの前に**出る（後ろに隠れない）。選ぶとサインインでき、上にアカウント（メールアドレス）が出る。左のメニューの「デプロイの一覧」「新しくデプロイ」が押せるようになる |
| 2 | 終了して（通知領域のアイコンを右クリック →「終了」。ジョブも期限のあるデプロイも無ければ、右上の × でも終了する）、もう一度起動する | 対話なしで、前のアカウントでサインインした状態で始まる |

### 3.2 デプロイの一覧（必須。Azure は読むだけ）
| # | 操作 | 確かめること |
|---|---|---|
| 3 | 「デプロイの一覧」→（出ていなければ）「読み込む」 | 本ツールでデプロイした環境が、サブスクリプション・グループ・状態・期限とともに出る（今の WinUI 3 版と同じ件数・中身） |
| 4 | 見出しを押して並べ替え、▽ で絞り込み、「含む文字」で絞り込み、見出しの右端のつまみで幅を変え、見出しをドラッグして順序を変える | WinUI 3 版と同じに動く。アプリを起動し直しても、列の幅と順序が残る。「列の幅と順序を初期値に戻す」で戻る |
| 4a | 見出しの名前をつかんで、ほかの列の見出しの上までドラッグする（ジョブの一覧でも） | ドラッグの途中は、動かす列が薄くなり、入る位置に青い線が出る。離すとその位置に動き、並べ替えは変わらない（2026-11-02 に作り直した。前はドラッグできなかった） |
| 4b | 見出しの ▽ →「左へ移動」「右へ移動」を何回か押す | 押すたびに列が 1 つずつ動き、▽ は開いたまま。いちばん左の列では「左へ移動」、いちばん右の列では「右へ移動」が押せない |
| 4c | 見出しのボタンにフォーカスを置き、Alt+Shift+→ を 2 回続けて押す | 同じ列が 2 列分右に動く（前は 2 回目で元の順序に戻った） |
| 5 | 1 行を選び、下の詳細で「パスワードを表示」→「表示する・伏せる」→ DB のパスワードの「コピー」。次に **Win+V**（クリップボードの履歴）を開く | パスワードが出て、コピーでき、**クリップボードの履歴に残らない**（WinUI 3 版と同じ） |
| 6 | 詳細の「状態を確認」 | 実行状況の画面が開き、Azure の状態（各アプリの状態・リソース・イメージ）が出る。「デプロイの一覧に戻る」で戻る |
| 7 | 詳細の URL を押す | 既定のブラウザーで Timetracker が開く |

### 3.3 予定の時刻（今回の修正。必須。Azure は変えない）
削除は「予定に追加」だけにして、時刻の前に取り消す（実行はしない）。

| # | 操作 | 確かめること |
|---|---|---|
| 8 | デプロイの一覧で 1 行（消してよいものでなくてよい）を選び、「Azure から削除…」→ アプリ名を入れる →「時刻」の時計のマークを押して、**今から 2 時間後**の時と分を選ぶ →「予定に追加」 | ジョブの一覧に移り、そのジョブの状態が「予定（MM/dd HH:mm）」で、**選んだ時刻**になっている |
| 9 | そのジョブの行を選び、「時刻」で**今から 3 時間後**を選ぶ →「選んだジョブの予定を変える」 | 「1 件の予定の変更（MM/dd HH:mm）をしました。」が**選んだ時刻**で出て、行の状態もその時刻になる（今回直した不具合） |
| 10 | 「時刻」で**今の時刻**（または今より前）を選ぶ →「選んだジョブの予定を変える」 | 「予定の時刻（…）は、今より後にしてください。」が出て、予定は変わらない |
| 11 | 「詳細」→ 実行状況の画面の「時刻」で今より前を選ぶ →「予定を変える」 | 「予定を変える」の下に「予定の時刻（…）は、今より後にしてください。」が赤で出て、状態は「予定」のまま（すぐ実行にならない） |
| 12 | 「時刻」の欄を押して、キーボードで分を 2 桁打つ（例: 「45」） | 打った 2 桁のとおりになる（1 桁目で切れない） |
| 13 | このジョブは残したまま、3.4 に進む（3.4 の後に取り消す） | |

## 4. 片付け
1. ジョブが残っていないことを確かめて、終了する（通知領域のメニューの「終了」）。
2. アプリを外す（管理者でない PowerShell）。アプリのデータ（設定・ジョブの記録）も一緒に消える。

   ```powershell
   Get-AppxPackage -Name TTDeployTool.BlazorPrototype | Remove-AppxPackage
   ```
3. 証明書を外す（管理者の PowerShell。発行先は評価版と同じ `CN=TTDeployTool` のため、拇印で選ぶ）。

   ```powershell
   $cer = New-Object System.Security.Cryptography.X509Certificates.X509Certificate2 "C:\Users\<名前>\Downloads\ttdeploytool-blazor-prototype-msix\TTDeployTool-BlazorPrototype.cer"
   Remove-Item "Cert:\LocalMachine\TrustedPeople\$($cer.Thumbprint)"
   ```
4. 3.8 を行ったら、Azure にテスト用のリソースが残っていないことを確かめる（Azure Portal か、今の WinUI 3 版のデプロイの一覧）。
