# Blazor Hybrid 版の実機での確認

- 目的: WinUI 3 版と同じ機能を実装した Blazor Hybrid 版（[`desktop-blazor-hybrid.md`](desktop-blazor-hybrid.md) の 16 章）を、オーナーの PC（Windows 11）で確かめる。CI では確かめられないもの（WAM のサインインの窓が前に出ること・見た目・本物の Azure での動き・人の操作での時刻の選択と日本語の変換）が中心
- 対象: CI（`ci.yml` の `blazor-prototype-windows` ジョブ）の成果物 `ttdeploytool-blazor-prototype-msix`（7 日で消える）。評価版（Desktop Preview）とは別のアプリ（`TTDeployTool.BlazorPrototype`）で、今の TTDeployTool と並べて入る。アプリのデータ（設定・ジョブの記録）も別
- **本物の Azure を使う**: サインインは WAM、Azure の読み書きは本物（モックではない）。デプロイ・削除をすると Azure が変わり、デプロイしたものには料金がかかる。3 章の必須の項目は Azure を変えない（削除は「予定に追加」だけにして、実行の前に取り消す）。デプロイと削除の実行は任意（3.5）で、テスト用のリソースグループで行う
- サインインのアプリ登録: CI の MSIX は、ビルドでクライアント ID を渡していない（Azure.Identity の既定。開発用）。会社のテナントの設定でサインインを断られたら、出た文字を記録する（評価版と同じクライアント ID で作り直す）
- 記録: `docs/REVIEW_ISSUES.md` の No.79。試作のときの確認（通知など。2026-10-31 にすべて OK）は設計書の 15.2

## 1. 受け取るもの
CI の実行の **Summary** の下の **Artifacts** から `ttdeploytool-blazor-prototype-msix` を取り出し、展開する。

| ファイル | 内容 |
|---|---|
| `TTDeployTool-BlazorPrototype-x64.msix` | Blazor Hybrid 版のアプリ（x64 だけ） |
| `TTDeployTool-BlazorPrototype.cer` | その実行だけで作った署名の証明書（公開鍵だけ） |
| `CHECK.md` | この手順書 |

## 2. 入れる
1. 前に試作（2026-10-31 の確認のもの）を入れたままなら、先に外す（管理者でない PowerShell）。証明書が実行ごとに違うため、上書きでは入らないことがある。

   ```powershell
   Get-AppxPackage -Name TTDeployTool.BlazorPrototype | Remove-AppxPackage
   ```
2. スタート メニューで「PowerShell」を右クリックし、「**管理者として実行**」で開いて、証明書を「ローカル コンピューター」の**信頼されたユーザー**に入れる（パスは置き換える）。

   ```powershell
   Import-Certificate -FilePath "C:\Users\<名前>\Downloads\ttdeploytool-blazor-prototype-msix\TTDeployTool-BlazorPrototype.cer" -CertStoreLocation Cert:\LocalMachine\TrustedPeople
   ```
3. 管理者でない PowerShell で、アプリを入れる。

   ```powershell
   Add-AppxPackage -Path "C:\Users\<名前>\Downloads\ttdeploytool-blazor-prototype-msix\TTDeployTool-BlazorPrototype-x64.msix"
   ```
4. スタート メニューの「**TTDeployTool（Blazor Hybrid の試作）**」で起動する（名前は試作のまま。ウィンドウの題は「TTDeployTool」）。サインインの画面が出る。

## 3. 確かめること
実機で確かめるのは、**CI の自動テストでは確かめられないもの**だけにしている（2026-11-14 に見直した。オーナーの依頼: 実機での確認の項目を少なくする）。WAM のサインインの窓、本物の Azure と会社のネットワーク、Windows の通知領域・通知・サインイン時の起動・ファイルの選択の窓、日本語の変換（IME）と時計の選択の部品、Windows のフォント・拡大率・明暗の設定での見た目。
画面の操作と表示（表の並べ替え・絞り込み・列の幅と順序、予定の時刻の入力、件数のカード、スライダー、料金の目安、右クリックのメニュー、ダブルクリック、詳細のコピーなど）は、3.6 の自動テストで毎回確かめているため、実機では見なくてよい（気づいたことがあれば記録する）。

各項目の結果（✔ / ✘ と、気づいたこと）を 5 章の表に記録する。今の WinUI 3 版と並べて動かして、見比べてもよい。

### 3.1 サインインと本物の Azure（必須。Azure は読むだけ）
| # | 操作 | 確かめること |
|---|---|---|
| 1 | 「サインイン」を押す | Windows のアカウントを選ぶ窓（WAM）が、**TTDeployTool のウィンドウの前に**出る（後ろに隠れない）。選ぶとサインインでき、左下にアカウントが出る |
| 2 | 終了して（通知領域のアイコンを右クリック →「終了」）、もう一度起動する | 対話なしで、前のアカウントでサインインした状態で始まる |
| 3 | 「デプロイの一覧」→「読み込む」 | 本ツールでデプロイした環境が、今の WinUI 3 版と同じ件数・中身で出る。本ツールのリソースを消してリソースグループだけが残った環境があれば、「リソースグループだけ」の行が出る |
| 4 | 「新しくデプロイ」の手順「スペックと利用可能期限」の右の「料金の目安」の下の文を見る | 「Azure の公開の価格表、MM/dd HH:mm に読んだ値」と出る（会社のネットワークで価格表を読めた）。「アプリに入れた価格」と出たら、読めなかったことを記録する |
| 5 | 1 行を選び、右の詳細で「パスワードを表示」→ DB のパスワードの「コピー」。次に **Win+V**（クリップボードの履歴）を開く | パスワードが出て、コピーでき、**クリップボードの履歴に残らない** |
| 6 | 右の詳細の「状態を確認」と、URL | 実行状況の画面に Azure の状態（各アプリの状態・リソース・イメージ）が出る。URL を押すと、既定のブラウザーで TimeTracker が開く |

### 3.2 Windows との連携（必須）
削除は「予定に追加」だけにして、9 で取り消す（実行はしない）。

| # | 操作 | 確かめること |
|---|---|---|
| 7 | デプロイの一覧で 1 行を選び、「Azure から削除…」→ アプリ名を入れ、「時刻」の**時計のマークを押して**、今から 2 時間後の時と分を選ぶ →「予定に追加」 | 時計の部品で選べ、ジョブの一覧でそのジョブの状態が「予定（MM/dd HH:mm）」の選んだ時刻になる |
| 8 | 予定のジョブがある状態で右上の × を押す。通知領域のアイコンにマウスを置き、左クリックで開く。もう一度 × で隠し、右クリック →「開く」。右クリック →「終了」→「キャンセル」。アプリを動かしたまま、スタート メニューからもう一度起動する | × で通知「バックグラウンドで実行を続けています」が出て、アイコンが残る。ツールチップに「TTDeployTool（予定 1）」のようにジョブの状況が出る。左クリック・「開く」でウィンドウが出る。「終了」で終わっていないジョブがある旨のダイアログが出て、「キャンセル」で終了しない。2 つ目は開かず、今のウィンドウが前に出る |
| 9 | ジョブの一覧で 7 のジョブを右クリック →「取り消し」 | 状態が「取り消し」になる（Azure は変わらない） |
| 9a | 7 の削除の画面で、アプリ名の欄を右クリック（先にアプリ名をコピーしておく） | 「切り取り・コピー・貼り付け・すべて選択」のメニューが出て、「貼り付け」で入る。入力欄でない所の右クリックでは、ブラウザーのメニュー（戻る・再読み込みなど）が出ない |
| 10 | 「設定」→「サインイン時の起動」を有効にする → Windows からサインアウトして、サインインし直す → 「設定」で無効に戻す | 有効にできる（初めては Windows が許可を尋ねることがある）。サインインし直すと、ウィンドウを出さずに通知領域にアイコンだけ出て、開くとサインインした状態。無効に戻せる |
| 11 | 「ローカル検証（Dry-run）」でパスワードを 2 つ入れ、「保存先を選んで保存」→ フォルダーを選ぶ →「フォルダーを開く」 | フォルダーの選択の窓が TTDeployTool の前に出る。エクスプローラーで保存したフォルダーが開く |

## 4. 片付け
1. ジョブが残っていないことを確かめて、終了する（通知領域のメニューの「終了」）。
2. アプリを外す（管理者でない PowerShell）。アプリのデータ（設定・ジョブの記録）も一緒に消える。

   ```powershell
   Get-AppxPackage -Name TTDeployTool.BlazorPrototype | Remove-AppxPackage
   ```
3. 証明書を外す（管理者の PowerShell。発行先は評価版と同じ `CN=TTDeployTool` のため、拇印で選ぶ）。

   ```powershell
   $cer = New-Object System.Security.Cryptography.X509Certificates.X509Certificate2 "C:\Users\<名前>\Downloads\ttdeploytool-blazor-prototype-msix\TTDeployTool-BlazorPrototype.cer"
   Remove-Item "Cert:\LocalMachine\TrustedPeople\$($cer.Thumbprint)"
   ```
4. 3.5 を行ったら、Azure にテスト用のリソースが残っていないことを確かめる（Azure Portal か、今の WinUI 3 版のデプロイの一覧）。
